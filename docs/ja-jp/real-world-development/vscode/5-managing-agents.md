GitHub Copilot をエージェントモードで使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行を自律的に行います。VS Code の Copilot Chat は、作業がユーザーのコンピューター上でリアルタイムに実行される間、各ツール呼び出しやファイル編集を確認できます。差分をインラインでレビューし、個々の変更を承認または拒否し、エディターを離れずに追加のプロンプトで会話を調整または拡張できます。

この演習では、次の内容を学習します。

- アクセシビリティエージェントの作業をリアルタイムで監視する。
- 提案されたファイル編集をレビューして承認する。
- セッション中にエージェントへ指示し、ハイコントラストモードに加えてライトモードの切り替え機能を追加する。

## シナリオ

[演習 4][previous-lesson]で使用したアクセシビリティカスタムエージェントが、ハイコントラストモードを実装しています。作業中にデザインチームから、既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替え機能も追加したいという要望がありました。新しい会話を最初から始めるのではなく、既存のセッションに指示して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調べたファイル、実行したコマンド、提案した編集を確認できます。ファイル編集は差分と **Keep** / **Undo** のコントロールとともにチャットに表示されます。

1. 演習 4 で使用した Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールしてツール呼び出しを確認します。ファイルの読み取り、ファイルの編集、実行を求められるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がチャットに表示されます。
    - 変更を承認するには **Keep** を選択します。
    - 変更を元に戻し、エージェントに再度作業させるには **Undo** を選択します。
4. チャット上部の **Files changed** インジケーターを開くと、このセッション中にエージェントが変更した作業ファイル全体を確認できます。

> [!NOTE]
> ターミナルコマンドの実行など、ツール呼び出しに権限が必要な場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、実行を許可できるコマンドのみ承認してください。

5. エージェントがハイコントラストモードの実装を完了するまで待ちます。変更内容をまとめた最終メッセージが表示されます。

## エージェントにライトモードを追加するよう指示する

ハイコントラストモードができたので、同じ会話でライトモードの切り替え機能を追加します。同じチャットセッションを続けるため、エージェントは前の作業のコンテキスト (変更したコンポーネント、スタイルの方針、設定した local storage のパターンなど) を保持しています。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは、すでに行った変更を調べ、そこからライトモードの追加を提案します。
3. ハイコントラストモードの場合と同じように、新しい編集をレビューします。各差分で **Keep** または **Undo** を選択します。
4. エージェントの進め方が希望と異なる場合 (たとえば、切り替え UI を意図しない方法でリファクタリングしようとした場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、明確にするための追加メッセージを送信します。

> [!TIP]
> 進行中のセッションに指示を出す方が、最初からやり直すよりも速く進められます。追加プロンプトで変更を依頼できます (「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使用する」)、方向を修正できます (「切り替えボタンを3つ目に増やさず、既存の設定パネルにライトモードを追加する」)、範囲を広げることもできます (「両方の切り替えにキーボードショートカットも追加する」)。

## 作業内容をレビューする

変更をコミットする前に、エージェントが編集した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧全体を確認します。Astro コンポーネント、スタイル、関連テストが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントが示したアクセシビリティの方針 (ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保持など) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで[変更を公開します][next-lesson]。

## まとめと次のステップ

Copilot Chat のエージェントモードを使って、進行中のセッションを監視して方向を調整しました。各ファイルの編集を確認し、変更を承認または拒否して、コンテキストを保ったまま追加プロンプトを送信し、作業を拡張しました。

このレッスンでは、次の内容を学習しました。

- エージェントの作業をリアルタイムで監視する。
- ファイル編集を個別に承認または拒否する。
- 追加プロンプトで進行中のセッションに指示する。

[次のレッスン][next-lesson]では、アクセシビリティ機能を PR として公開し、このラボを通してローカルのカスタムエージェントが作成した変更をレビューします。
